# Сайт Buba Tea

Статический сайт под Google Ads. Меню тянется из Poster POS, поэтому вести его
руками не нужно.

## Языки

Сейчас собирается **только английский** — доводим его. Русские и индонезийские
тексты никуда не делись, лежат в `content/i18n/`, просто не собираются.

Включить обратно — одна строка в `content/business.json`:

```json
"site": { "languages": ["en", "ru", "id"] }
```

Тогда сами появятся страницы `/ru/` и `/id/`, переключатель языков в шапке
и разметка `hreflang`. Пока язык один, `hreflang` не выводится вовсе — Google
считает ссылку страницы саму на себя лишним шумом.

Зависимостей нет — нужен только Node 18+. `npm install` делать не надо.

## Команды

```bash
cd site
npm run sync    # забрать актуальное меню из Poster
npm run build   # собрать сайт в dist/
npm run check   # проверить перед публикацией (битые ссылки, SEO, заглушки)
npm run dev     # собрать и открыть на http://localhost:4321
```

## Что где лежит

| Путь | Что это |
|---|---|
| `content/business.json` | **Единственный файл, который правишь руками.** Адрес, часы, ссылки, номера, ID аналитики |
| `content/i18n/*.json` | Все тексты сайта. `en` — основной, `ru` и `id` — переводы |
| `content/menu.json` | Меню из Poster. Генерируется, руками не трогаем |
| `src/pages/*.mjs` | Разметка страниц |
| `src/styles.css` | Дизайн |
| `src/app.js` | Скрипт на клиенте: меню, cookie, часы работы, форма → WhatsApp |
| `public/` | Логотипы, фото, шрифты, иконки |
| `dist/` | Собранный сайт. Именно его выкладываем |

## Посмотреть, как сайт выглядит заполненным

`content/business.demo.json` — тот же конфиг с выдуманными адресом, номерами и
ссылками. Нужен только чтобы увидеть сайт целиком, пока настоящие данные не собраны:

```bash
cp content/business.json content/business.backup.json
cp content/business.demo.json content/business.json
npm run dev
# посмотрела — вернула обратно:
cp content/business.backup.json content/business.json
```

⚠️ Публиковать сборку с демо-данными нельзя: там несуществующий адрес и номер.

## Как поменять контент

**Меню, цены, фото блюд** — только в Poster. Потом `npm run sync && npm run build`.
Правило то же, что в приложении: Poster — единственный источник правды.

**Адрес, часы, ссылки на доставку, номер WhatsApp** — `content/business.json`.
Незаполненные поля помечены `TODO`; блоки с ними на сайте просто скрыты,
а сборка каждый раз напоминает, чего не хватает.

**Тексты** — `content/i18n/en.json`. Пока язык один, правим только его.
Когда английский утвердим, с него переведём `ru.json` и `id.json` и включим языки.

## Страницы

| Адрес | Под какую рекламу |
|---|---|
| `/` | брендовые запросы, «bubble tea Bali» |
| `/menu/` | «matcha Canggu», «bubble tea menu» |
| `/delivery/` | «bubble tea delivery», «matcha delivery Bali» |
| `/catering/` | «wedding catering Bali», «coffee cart rental» — самый дорогой чек |
| `/visit/` | «bubble tea near me», локальная реклама и Google Maps |
| `/privacy/`, `/terms/` | обязательны для Google Ads, из карты сайта исключены |

Русские и индонезийские версии появятся под префиксами `/ru/` и `/id/`, когда включим языки.

## Аналитика и конверсии

ID вписываются в `business.json` → `analytics`. Пока они пустые, скрипты Google
на сайт не подключаются вообще.

Отслеживаются пять действий: `whatsapp`, `directions`, `delivery`, `cateringLead`, `call`.
Каждое уходит в GA4 как событие `buba_<действие>`, а если для него задана метка
в `conversionLabels` — ещё и конверсией в Google Ads.

Согласие на cookie реализовано через Google Consent Mode v2: до ответа гостя
всё запрещено. Это требование для трафика из ЕС, а туристов оттуда много.

## Публикация

`dist/` — обычные HTML-файлы, подходит любой хостинг. Для Vercel настройки уже
лежат в `vercel.json`: команда сборки, папка, заголовки кеша.

⚠️ Перед запуском рекламы нужен настоящий домен. На технических адресах вроде
`*.vercel.app` объявления работают плохо, а часть форматов не проходит модерацию.

## Секреты

Токен Poster берётся из `site/.env`, а если его нет — из `.env` бэкенда приложения
(`Claude Projects/BubaApp/apps/backend/.env`). В собранный сайт он не попадает:
синхронизация происходит на твоей машине, наружу уезжает только готовый `menu.json`.
